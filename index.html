01 / The distinction

Door number or occupied room?

A port helps the kernel find an application. A socket is the kernel object through which that application communicates.

PORT
80

A label in a packet

A 16-bit integer from 0 to 65535, interpreted separately for TCP and UDP.

  • Travels in the TCP or UDP header
  • Helps select a service
  • Has no buffers, state, or owner
≠
SOCKET
fd 6

A living kernel object

Created by socket(), exposed to a process as a file descriptor, and optionally associated with an address by bind().

  • Owns send and receive buffers
  • Tracks protocol state
  • Has a lifetime and process owner
⌂
The apartment analogy

The IP address is the building. A port is the apartment number painted on a door. A socket is the actual leased apartment: it has an occupant, working mailbox, and a particular conversation with a visitor.

03 / Packet journey

What Linux actually does

  1. 1

    Read the header

    Extract source and destination addresses, ports, and protocol.

  2. 2

    Look up the socket

    Match the packet’s tuple against kernel socket tables.

  3. 3

    Queue the bytes

    Place payload in that socket’s receive buffer.

  4. 4

    Wake the process

    Notify the process waiting on the file descriptor.

KEY IDEA

The port is a lookup key. The socket is the place the data goes.

04 / Why it matters

Four mysteries, explained.

01

1,000 web clients

One listening socket on port 80 can create thousands of established sockets. Each client has a different 5-tuple, so every byte reaches the right conversation.

same :80 · unique peers
02

SO_REUSEPORT

Multiple listening sockets may intentionally bind the same address and port. Linux distributes new flows between them for scalable server workloads.

many sockets · one :8080
03

TIME_WAIT

The kernel retains a recently closed TCP connection tuple—not a universally “locked port.” Whether reuse is possible depends on the new tuple and bind rules.

tuple retained · not a lock
04

Network namespaces

Each namespace has its own networking stack and socket tables. Two containers can both listen on 0.0.0.0:80 without colliding.

same :80 · separate worlds
