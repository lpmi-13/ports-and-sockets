A field guide

One connection, three names.

The same TCP connection gets named three ways, because three different actors each need to reach it. The remote host and the kernel's packet demux use the port. The process uses a file descriptor — read(4), never read(:80). The kernel owns the socket itself: the buffers, the TCP state, the object both sides point at.

Watch one nginx connection through all three lenses at once. Accept a client and it appears everywhere — a flow on the wire, a socket in the kernel, an fd in the process. Ask getsockname() and watch the process syscall into the kernel just to learn its own port.

socket:[12346] is the join key — it shows up in both lsof (the process's fd) and the kernel's socket table. The port routes packets in, the fd reads them out, and the socket in the middle is the thing that's actually real.
