A field guide

A port is a number. A socket is the endpoint.

A port is a 16-bit number sitting in a packet header — no buffer, no state, no owner. A socket is a real kernel object with receive and send buffers, protocol state, and a file descriptor. The socket is what actually holds your data.

Step forward with Next (or the arrow keys) to walk one packet up the kernel stack. Watch the socket table narrow: the port gets the packet to a bucket of sockets that share it; the full 5-tuple picks the one socket that receives.

Tap any socket row to select it, or an anatomy row below to see its real fields as ss, tcpdump and /proc would show them. Hit New packet for a fresh arrival — an established connection, a brand-new SYN, a UDP datagram, or a packet to a closed port.
