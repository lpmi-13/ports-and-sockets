A field guide

A port is a number. A socket is the endpoint.

A port is the address a server listens on — there's exactly one. A socket is a connection — there are many, one per client, and it's the file descriptor your code actually read()s and write()s.

Operate a real nginx server across three short acts. Accept clients and watch one port fan out into many sockets — then push it until it breaks. The errors you hit in production are exactly what tell the two apart.

Use the action buttons to drive the server, the acts to move between scenes, and open any card to see the real ss, lsof and error output — the stuff behind address already in use, too many open files, and cannot assign requested address.
